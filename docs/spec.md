# 星图索引与项目清理 Spec

## 背景

当前首页使用力导向图展示目录与笔记。目录层级较浅、笔记数量较少时，这种方式具有良好的探索感；当某个目录下积累较多笔记后，文章节点会分散在图中，难以按照名称快速找到目标。

项目同时存在若干可能已经被替代或不再使用的文件，但整个工作区包含站点内容、主题子模块、写作辅助工具以及尚未提交的用户改动。清理必须建立在完整审计和用户逐项批准的基础上。

## 目标

- 保留首页力导向图作为上层目录的探索入口。
- 进入二级及更深目录后，以稳定、按名称排序的列表展示笔记。
- 让列表在视觉上延续当前星图的空间关系和整体风格。
- 审计整个项目的清理候选项，并确保任何删除都经过用户明确批准。

## 功能需求

- F1：首页继续使用力导向图展示和展开上层目录，保留缩放、拖动及状态恢复能力。
- F2：进入二级或更深目录时，以列表展示该目录下所有后代笔记；一级叶子目录直接包含笔记时也使用列表。
- F3：列表始终按照显示名称升序排列，不提供搜索、过滤或排序切换。出现同名笔记时显示相对目录路径以便区分。
- F4：点击列表项直接进入对应文章。列表展开时保留当前目录节点和路径上下文，并弱化无关节点。
- F5：桌面端显示侧边索引轨道；窄屏设备在图下方展开列表，不出现重叠和横向滚动。
- F6：进入文章再返回首页时，恢复先前展开的目录和索引上下文。
- F7：审计整个项目的文件用途。任何删除操作前，都必须向用户报告候选文件的用途和删除影响，并获得明确批准。

## 非功能需求

- N1：保留现有玻璃质感、背景氛围和力导向图的整体视觉风格；列表应表现为图节点自然延伸出的界面，而不是独立的传统文章列表页。
- N2：展开包含大量笔记的目录时，列表必须保持稳定可读，不能因节点碰撞、持续抖动或动画阻塞影响浏览。
- N3：桌面鼠标和移动端触摸均可完成目录展开、列表浏览及文章打开；交互元素具有明确的可点击状态。
- N4：尊重系统的“减少动态效果”设置；普通动画只在状态切换时发生，不进行持续循环的装饰动画。
- N5：不引入新的运行时框架或远程依赖，沿用现有站点构建体系。
- N6：不改变文章目录结构、现有文章地址或内容数据格式。
- N7：不直接修改第三方主题子模块；自定义实现继续位于项目自身的布局和资源范围内。
- N8：生产构建必须通过，并保持桌面端与移动端现有文章页面能力不回退。
- N9：项目清理必须可审计。候选文件在删除前逐项说明，未经用户批准一律保留。

## 不做的事

- 不实现文章搜索、全文检索、标题过滤、搜索快捷键或搜索结果页面。
- 不提供排序方式选择；列表固定按显示名称升序排列。
- 不修改文章内容、标题、目录层级、永久链接或分类方式。
- 不重做文章页面、文章目录、Zima Blue 动画、Mermaid 或主题切换功能。
- 不修改或升级第三方主题、站点生成工具和可视化依赖。
- 不新增标签视图、时间线、收藏或阅读历史等额外导航功能。
- 不删除任何尚未获得用户明确批准的文件，即使它看起来未被引用。
- 不自动提交、推送或部署本次改动。

## 验收标准

- AC1（F1）：打开首页时仍显示顶层力导向图；目录节点可以展开、收起和拖动，页面缩放正常。
- AC2（F2）：进入二级目录后，界面显示该目录全部后代笔记的列表，不再把这些文章散布成力导向节点；一级叶子目录也采用相同行为。
- AC3（F3）：使用包含中文、英文、数字及重复标题的示例数据验证，列表始终按照显示名称稳定升序排列；重复标题旁显示各自的相对路径。
- AC4（F4）：点击任意列表项进入对应文章；打开列表时当前目录及路径清晰可见，无关图节点被弱化；关闭后图状态恢复。
- AC5（F5）：在桌面宽度和 360 像素移动端宽度下验证，列表均可完整阅读和点击，不出现控件重叠、文字不可辨认或页面横向滚动。
- AC6（F6）：展开一个目录并进入文章，再返回首页，原目录展开状态和索引上下文得到恢复。
- AC7（F7）：完成一次覆盖整个项目的清理候选审计。每个候选项都说明用途、引用情况、保留价值、删除风险及建议；报告提交后不发生任何删除。
- AC8（F7）：仅删除用户明确批准的候选文件；未批准项目以及实施前已有的工作区改动保持不变。
- AC9（F1–F6）：目录包含较多笔记时，索引列表保持固定位置，不参与力模拟，也不会持续抖动。
- AC10（F1–F6）：生产构建成功；首页、文章页、文章目录、主题切换、Mermaid 和 Zima Blue 页面能力没有可观察回退。
- AC11（全部）：没有修改第三方主题子模块、文章内容路径、现有文章地址，也没有新增远程运行依赖。
