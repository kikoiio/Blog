# 星图索引与项目清理 Plan

## 架构概览

### 目录数据层

在现有目录树之上增加节点层级判断、递归收集后代笔记、稳定名称排序和重复标题识别能力。原始 Hugo 页面数据格式保持不变。

### 图导航控制层

现有力导向图继续负责顶层和一级非叶子目录。点击目录后，由图导航控制层判断继续展开图节点还是打开索引轨道。进入索引模式后，不再把当前目录下的文章加入力模拟。

### 索引轨道组件

索引轨道接收当前目录、目录路径和排序后的笔记列表，使用普通 DOM 元素渲染标题列表。组件负责目录上下文、文章数量、重复标题路径、列表导航、关闭操作以及桌面和移动端共同的页面结构。

### 图与列表的视觉协调

索引打开时保留选中目录节点，弱化无关节点，并停止不必要的模拟运动。列表通过一次性展开动画与节点建立视觉联系；减少动态效果模式下取消动画。

### 状态恢复

扩展现有会话状态，保存已展开目录、当前图焦点和打开的索引目录。进入文章前写入状态，返回首页后重建目录图并重新打开对应索引。

### 项目清理流程

全项目扫描结果写入独立的 `docs/cleanup-audit.md`。每个删除候选记录用途、引用证据、保留价值、删除风险和建议。首次审计只生成文档；收到用户明确批准后，才执行获批删除并重新验证。

## 核心数据结构

### `PageData`

保留现有页面数据结构：

```ts
interface PageData {
    path: string;
    title: string;
    url: string;
}
```

### `TreeNode`

继续作为纯目录树节点，不混入索引界面状态：

```ts
interface TreeNode {
    name: string;
    children: Map<string, TreeNode>;
    pages: PageData[];
}
```

### `IndexEntry`

```ts
interface IndexEntry {
    title: string;
    url: string;
    directoryPath: string;
    showPath: boolean;
}
```

`showPath` 仅在同一索引中出现重复标题时为 `true`。

### `IndexViewModel`

```ts
interface IndexViewModel {
    title: string;
    treePath: string;
    entries: IndexEntry[];
}
```

### `SavedGraphState`

```ts
interface SavedGraphState {
    expandedPaths: string[];
    focusPath: string;
    indexPath: string;
}
```

不保存搜索词、排序选择或列表滚动位置。

### 目录数据接口

```ts
function collectDescendantPages(node: TreeNode): PageData[];

function buildIndexEntries(node: TreeNode): IndexEntry[];

function shouldOpenIndex(node: GraphNode): boolean;
```

- `collectDescendantPages` 递归收集当前目录下全部笔记。
- `buildIndexEntries` 完成稳定升序排序和重复标题标记。
- `shouldOpenIndex` 根据目录深度和是否为一级叶子目录决定使用列表还是继续展开图。

### 索引组件接口

```ts
interface IndexPanelController {
    open(model: IndexViewModel): void;
    close(): void;
    isOpen(): boolean;
    currentPath(): string;
}

interface IndexPanelCallbacks {
    onNavigate(entry: IndexEntry): void;
    onClose(): void;
}

function createIndexPanel(
    container: HTMLElement,
    callbacks: IndexPanelCallbacks
): IndexPanelController;
```

索引组件只负责 DOM 渲染和用户操作，不直接访问力模拟或会话存储。

## 模块设计

### 目录树模块

**职责：**

- 从页面路径构建目录树。
- 递归收集目录后代笔记。
- 生成按名称升序排列的索引条目。
- 识别重复标题并标记是否需要显示路径。
- 判断目录是否应进入索引模式。

**对外接口：** `buildTree`、`hasContent`、`collectDescendantPages`、`buildIndexEntries`、`shouldOpenIndex`。

**依赖：** 仅依赖共享类型，不操作 DOM 或会话状态。

### 索引轨道模块

**职责：**

- 创建和维护索引轨道 DOM。
- 显示目录名称、路径、文章数量及排序后的列表。
- 处理列表项导航和关闭操作。
- 使用安全文本节点展示标题及路径。
- 管理打开、关闭和减少动态效果状态。

**对外接口：** `createIndexPanel`、`IndexPanelController`、`IndexPanelCallbacks`。

**依赖：** 仅依赖索引数据类型，不依赖 D3。

### 图导航模块

**职责：**

- 初始化 D3 力导向图。
- 处理目录展开、收起、拖动、缩放和焦点样式。
- 根据目录层级选择继续展开图或打开索引。
- 打开索引时停止无关模拟、保留选中目录并弱化背景节点。
- 关闭索引时恢复图状态。
- 进入文章前持久化当前上下文。

**对外接口：** 仍由首页脚本自动初始化，不新增全局 API。

**依赖：** 目录树、索引轨道、状态、节点渲染和共享类型模块。

### 状态模块

**职责：**

- 保存展开目录、图焦点和当前索引路径。
- 读取旧格式状态时提供兼容默认值。
- 清理无效或无法恢复的状态。

**对外接口：** `saveState(expandedPaths, focusPath, indexPath)`、`loadState()`、`clearState()`。

**依赖：** 仅依赖共享状态类型。

### 首页模板

**职责：**

- 保留图容器和页面数据。
- 提供索引轨道的语义化挂载区域、关闭按钮及必要标签。
- 不在模板中实现排序或目录判断逻辑。

**依赖：** Hugo 页面数据和编译后的首页脚本。

### 首页样式

**职责：**

- 定义桌面侧边轨道和移动端图下列表布局。
- 延续当前玻璃质感、颜色变量及节点风格。
- 提供打开、关闭、背景弱化和减少动态效果样式。
- 防止窄屏横向滚动和列表文字不可读。

### 清理审计文档

**职责：**

- 记录完整项目扫描方法。
- 列出每个删除候选的用途、引用证据、保留价值、删除风险和建议。
- 记录用户的保留或删除决定。
- 在获得批准前不触发任何文件删除。

## 模块交互

### 首页初始化

```text
Hugo 页面数据
    → 构建目录树
    → 初始化索引轨道
    → 读取会话状态
    → 重建已展开目录
    → 恢复图焦点
    → 若存在有效索引路径，则重新打开索引
```

旧状态缺少索引路径时按空值处理，不影响现有状态恢复。

### 点击目录节点

```text
点击目录
    → 判断目录层级与叶子状态
        ├─ 一级且仍有子目录 → 继续展开力导向图
        └─ 二级及更深 / 一级叶子
             → 递归收集笔记
             → 按显示名称稳定排序
             → 标记重复标题
             → 聚焦当前节点并弱化无关节点
             → 打开索引轨道
             → 保存索引路径
```

### 打开文章

```text
点击索引条目
    → 保存已展开目录、当前焦点和索引路径
    → 跳转到对应文章
```

### 关闭索引

```text
点击关闭
    → 收起索引轨道
    → 清除已保存的索引路径
    → 恢复目录图的正常透明度和模拟状态
    → 焦点回到该索引目录的父目录
```

### 从文章返回首页

```text
返回首页
    → 重建已展开目录
    → 定位保存的索引目录
        ├─ 路径仍有效 → 恢复节点焦点并打开索引
        └─ 路径已失效 → 清除无效索引状态，显示正常目录图
```

### 响应式切换

宽度变化时，图只更新画布尺寸和中心力；索引轨道由 CSS 在侧边布局与图下布局之间切换，不销毁或重新排序数据。

### 项目清理

```text
扫描整个项目
    → 排除构建产物与第三方子模块内部文件
    → 检查第一方文件用途和引用关系
    → 生成清理候选报告
    → 等待用户决定
        ├─ 保留 → 记录决定，不修改文件
        └─ 删除 → 仅删除获批文件
                    → 重新扫描引用
                    → 生产构建
                    → 回写实际结果
```

第三方主题子模块作为一个整体审计，不逐个评估其内部文件。

## 技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 图与列表边界 | 二级及更深目录、一级叶子目录进入索引模式 | 保留上层探索感，同时避免文章数量扩大图复杂度 |
| 列表承载方式 | 使用图容器之外的普通 DOM 元素，不在 SVG `foreignObject` 中排列文章 | 文本更稳定、响应式更可靠，也不会参与 D3 模拟 |
| 后代文章范围 | 递归扁平化当前目录的全部后代笔记 | 用户无需继续逐层展开即可按名称找到目标 |
| 名称排序 | 使用中文区域感知、数字友好的比较规则；标题相同时以目录路径作为稳定次级顺序 | 中英文和数字混排更自然，并保证每次顺序一致 |
| 重复标题 | 仅对重复标题显示相对目录路径 | 正常条目保持简洁，同时避免同名文章无法区分 |
| DOM 创建 | 使用 DOM API 和 `textContent`，不拼接文章标题 HTML | 避免特殊字符破坏结构或形成注入风险 |
| 状态存储 | 沿用会话级浏览器存储，增加索引路径字段并兼容旧状态 | 维持当前进入文章后返回的体验，不引入长期状态 |
| 响应式布局 | 同一份索引 DOM 通过 CSS 在侧栏与图下布局之间切换 | 避免窗口变化时重建数据和丢失上下文 |
| 动画策略 | 仅在打开、关闭和焦点变化时执行短过渡；减少动态效果模式下关闭过渡 | 保留趣味性但不干扰阅读或持续消耗资源 |
| 运行依赖 | 只使用现有构建体系、D3 和浏览器原生能力 | 避免增加下载、构建和维护成本 |
| 清理范围 | 扫描整个第一方项目；第三方主题作为整体审计 | 覆盖项目遗留项，同时避免破坏子模块完整性 |
| 删除控制 | 审计、用户批准、删除、重验四步分离 | 确保任何文件删除都可解释、可追踪且经过授权 |
| 用户现有改动 | 记录实施前状态并避开已有删除和未跟踪内容 | 防止本次改造覆盖或混入用户正在进行的工作 |
